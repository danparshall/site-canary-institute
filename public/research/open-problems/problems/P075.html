P075 Network interlock performance

Can an inline network interlock enforce a signed list of allowed peers at full line rate (800 Gb/s to 1.6 Tb/s)?

Whether an inline network interlock can enforce a signed peer allow-list at full line rate: latency, firmware updates, key setup, in-network-compute switches, NVLink traffic and DMA spoofing.

Status

Started Built, not measured: Amodo report a working prototype in which a central controller leases traffic quotas to NVIDIA BlueField network cards that enforce them, and hardware-accelerated encryption between nodes, with keys the controller can revoke. Membership by key is a form of the allowed-pairs list the problem asks about, but no peer allow-list has been built as such, and no line-rate or latency figures are published. The full interlock design is in flexHEG Part 2 (Petrie & Aarne 2025), with the network card as the retrofit location; encrypting all NVLink traffic is estimated at about 3% of H100 compute (a desk estimate).
