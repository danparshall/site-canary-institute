P099 Hardware scope and chip classification

Which chip specifications predict training throughput well enough to set a regime's hardware scope, and where do consumer/edge parts fall relative to that line?

Which chips and specs a regime covers, how chip capability is classified and measured, and where consumer-GPU and edge cases fall.

Terms: H100-equivalent (H100e): a common unit that counts mixed accelerators as multiples of one Nvidia H100 data-centre GPU, so fleets of different chips can be compared on one scale. N: the factor by which a cluster is larger when each chip has 1/N of the throughput.

Status

Analyzed Simulated (a distributed-training cost model calibrated to Covenant-72B, not a measured run): adds a 1,280 GB HBM memory threshold beside the 16-H100-equivalent cluster line for a 10^25 FLOP evasion, showing memory capacity, not only FLOP/s, matters for scope. Consumer/edge clause: the same desk analysis places 4-8 GPU workstations, DGX-class servers and GDDR parts below that threshold, also paper only. No throughput-prediction study; nothing measured. '1025' is the saved text's rendering of 10^25.

imposing the memory limit reduces the maximum unregistered per-node model from 240B to roughly 91B parameters, forces the evader to operate approximately five times as many nodes for equivalent model quality, and raises the cost of illicitly developing a 1025 FLOP model by roughly 50%.
Rahman (2026), Does Distributed Training Undermine Compute Governance? (MIRI), arXiv 2605.29359 (2026-05-28), L1279–1283
