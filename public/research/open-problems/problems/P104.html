P104 Training-procedure and code verification

Can a declared architecture, optimiser schedule and code be checked against an executed run, catching a deliberately mis-declared one?

Checking training procedure and code against declarations.

Status

Started Delegation setting: a client fixes the program and several untrusted providers run it; a referee localises any divergence to one training step and one operator, re-executes it and rules, so an execution that departs from the declared program is caught given bitwise reproducibility (the RepOps library). Implemented and benchmarked on DistilBERT and Llama-3.1 1B and 8B training and inference, FP32 only, about 60% overhead on an A100. Not shown: a prover who both writes and mis-declares the code, frontier scale, or any check of the declaration's content (architecture, optimiser schedule) beyond re-execution; Choi et al. (2023) re-execute segments of a declared transcript on GPT-2 in the same spirit, for data rather than code.

Our implementation shows that refereed delegation achieves both strong guarantees for clients and practical overheads for compute providers.
Arun et al. (2025), Verde: Verification via Refereed Delegation for Machine Learning Programs, arXiv 2502.19405 (2025-02-26), L50–53
