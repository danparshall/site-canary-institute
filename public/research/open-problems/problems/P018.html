P018 Telemetry read-path integrity and accuracy

Does any shipping GPU expose an authenticated, tamper-resistant power/clock telemetry path a root-privileged host cannot forge or replay?

Authenticity and accuracy of GPU power/clock telemetry read paths.

Terms: NVML (Nvidia Management Library): the standard software interface for reading a GPU's power, clock and temperature.

Status

Analyzed A requirements design for the read path (attested enclave or secure-boot-chained firmware, hardware-rooted signing, nonce-binding against replay, attested monitoring software), pointing to the flexHEG guarantee-processor designs; nothing built, and no shipping GPU is named as having it - every source says such paths 'do not yet exist'. Telemetry accuracy (sampling fraction, counter error) is in the statement but not the headline: related, with measured work (Yang et al. 2023: only 25% of runtime sampled for power on A100/H100).

The monitoring agent must read counter values from a source the adversary cannot tamper with—e.g., an attested enclave on the GPU firmware boundary (Aarne et al., 2025) or a verified read path through secure-boot-chained firmware (Petrie, 2025; O’Gara et al., 2025). Without this, an adversary with software privilege simply returns forged values.
Rahman & Tajdari (2026), Detecting Hidden ML Training With Zero-Overhead Telemetry (MIRI; arXiv 2606.19262) (2026-06-17), L776–783
